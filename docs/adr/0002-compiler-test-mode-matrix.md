# 2. Матрица режимов в компиляторном тест-харнесе

Статус: принято (2026-07-04)

## Контекст

Компиляторные output-comparison кейсы (`tasks/compiler_tests/cases2/`, `cluster_cases/`)
сверяют выход нашего компилятора с эталоном Оригинала. Сегодня один кейс компилируется
ровно в **одном** режиме: поле `dev` в `config.json` *пинит* режим, эталон — единственный
`case-svelte.js`. Из 1191 кейса 83 зафиксированы на `dev:true` — их `case-svelte.js`
содержит **dev-выход**, остальные — prod-выход.

Проблема: parity dev-режима не покрыт систематически. Кейс, написанный под prod, никогда не
проверяется в dev, и наоборот. Регрессия dev-кодгена на prod-написанном кейсе невидима.

Цель: каждый output-comparison кейс прогоняется через **набор режимов**, у каждого свой
эталон и своя сверка. Фаза 1 — client `{prod, dev}`. Фаза 2 (за скобками) — `+{server-prod,
server-dev}`; раскладка и механизм проектируются расширяемыми под неё, но не реализуются.

## Решение

Ввести **матрицу режимов**: режим — ортогональная ось, которую гоняет **сам тестовый макрос**,
а не поле в `config.json`.

1. **Ось владеет режимом, config.json — нет.** `assert_compiler` / `assert_compiler_module`
   компилируют вход в каждой ячейке матрицы и сверяют с её эталоном. Поле `dev` перестаёт
   выбирать режим: харнес его больше не читает в опции, `generate.mjs` его перекрывает
   пер-ячейку. `config.json` несёт только **mode-инвариантные** опции (`runes`, `namespace`,
   `name`, `customElement`, `experimental.async`, `preserveWhitespace`, `preserveComments`,
   `rootDir`, `filename`).

2. **Reference-варианты — суффикс-сиблинги.** `case-svelte.js` **всегда** = client-prod-эталон;
   `case-svelte.dev.js` = client-dev-эталон. Наш выход зеркалит: `case-rust.js` / `case-rust.dev.js`.
   Фаза 2: `case-svelte.ssr.js` / `case-svelte.ssr.dev.js`. Оба эталона пишутся **всегда**, даже
   когда prod и dev побайтово равны — макрос без ветвлений (`prod vs .js`, `dev vs .dev.js`).

3. **Список тестов не меняется.** Матрица живёт внутри тела `assert_compiler` — 1185
   `#[rstest]`-функций и `compiler_case!`-регистрации остаются как есть. `just generate` список
   тестов не трогает (как и раньше).

4. **Радиус — component + module, без sourcemap.** Ось получают `.svelte` и `.svelte.js`/`.svelte.ts`
   кейсы в `cases2` и `cluster_cases`. Sourcemap-кейсы (цель — инварианты карт) и диагностические
   (`just test-diagnostics`, отдельная команда) вне scope. CSS mode-инвариантен → единственный
   `case-svelte.css`, сверяется на prod-ячейке.

5. **Зелёность — big-bang, без baseline.** Обе ячейки сверяются строго; красный кейс держится
   красным, пока dev-расхождение не починено. Baseline / ratchet-список отвергнут (см. Альтернативы),
   но остаётся «на полке» как fallback. Замер после подключения плумбинга (2026-07-04):
   **506 dev-расхождений** — 171 в `cases2` (из 1191), 335 в `cluster_cases` (из 1023), из них
   8 жёстких паник (семейство `bind_group` в `{#each}`, `svelte_codegen_client/src/lib.rs:148`).
   Prod-ячейки, CSS и sourcemap — **0 регрессов**.

### Миграция 83 dev-пиновых кейсов

Первый `just generate` перегенерит их `case-svelte.js` из dev в **prod**, а нынешний dev-выход
уедет в `case-svelte.dev.js` (побайтово = тому, что мы уже эмитим → их dev-ячейка зелёная сразу).
Ключ `dev` из их `config.json` удаляется (для config'ов вида `{"dev":true}` — удаляется весь файл).

## Последствия

- Systematic dev-parity: регрессия dev-кодгена на любом кейсе ловится.
- ~2× reference-файлов (`+case-svelte.dev.js` на кейс, 2219 создано), одна миграционная правка.
- `just generate` компилирует каждый файл дважды (prod+dev) в одном node-проходе.
- `.gitignore` расширен `**/case-rust.dev.js` (наш dev-выход материализуется прогоном, не коммитится).
- После подключения `just test-compiler` красный (506 dev-ячеек) до закрытия dev-parity; prod
  зелёный. Burn-down — вне этого ADR (кластеры: `bind:group`-паника, `svelte:*`, css-в-dev,
  `each_destructured`, `const_tag`, stores, `diagnose_legacy`).
- Расширение на SSR (фаза 2) — добавление двух ячеек и суффиксов, без пересмотра механизма.

## Альтернативы

- **`config.json` как база + overlay режима.** Config продолжает нести `dev`, матрица добавляет
  противоположную ячейку. Отвергнуто: ось и config пересекаются, режим размазан по двум местам.
- **Baseline / ratchet-список расхождений.** Централизованный allow-list dev-ячеек, где mismatch
  не роняет тест, с ratchet «совпал → убери из списка». Отвергнуто как основной механизм в пользу
  big-bang (замер показал малый N); оставлено как fallback.
- **Per-case маркер `devPending` в config.json.** Тот же смысл, но долг размазан по сотням папок.
- **Поддиректории по режиму** (`client/`, `client-dev/`). Отвергнуто: массовый rename 1191 кейса
  и слом всех путей в харнесе/generate ради визуальной чистоты.
- **Отдельный `#[rstest]` на (кейс × режим).** Удваивает список функций (2370+), рвёт инвариант
  «один макрос — оба режима».
