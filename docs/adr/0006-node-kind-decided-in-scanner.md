# 6. Вид узла шаблона решает сканер; фаза разбора JS его не переклассифицирует

Статус: принято (2026-07-25)

## Контекст

**Declaration-тег** (`{const x = …}` / `{let x = …}`) сканер узнаёт лексически, по слову на
границе. Для `const` / `let` / `var` / `interface` / `enum` догадка однозначна — это
зарезервированные слова. Для `type` нет: `{type X = 1}` — объявление типа, `{type instanceof
Object}` — обычное выражение с `type` в роли идентификатора.

Оригинал снимает неоднозначность разбором: парсит тело как statement и смотрит, что вышло —
`ExpressionStatement` значит «это не декларация, а @-тег-выражение». У нас такой ответ приходит
позже: сканер уже выдал токен, узел шаблона уже построен, встроенный JS разбирается отдельной
фазой поверх готового дерева.

## Решение

Вид узла шаблона решает **парсер** (сканер + сборка дерева) и только он. Фаза разбора JS
заполняет узлы, но вид узла не меняет.

Следствие: `{type …}` классифицируется лексически, и на выражениях, где `type` — идентификатор
(`{type instanceof X}`, `{type in obj}`), мы расходимся с Оригиналом. Расхождение принято, а не
закрыто; сэмпл припаркован как `input.svelte.skip`.

## Последствия

- Узел рождается один раз, со своим видом; ни одному даунстрим-слою не нужно допускать, что
  вид узла ещё изменится.
- `{type …}` в позиции выражения отвергается с `declaration_tag_invalid_type`. Известная дыра,
  не баг к быстрой правке.
- Закрыть её можно только тем, что даёт ответ до сборки узла, — разбором тела внутри парсера,
  до того как узел попал в `AstStore`.

## Альтернативы

- **Переклассифицировать узел после разбора тела** (пометить его на фазе разбора JS и переписать
  в `AstStore` следом). Отвергнуто: сканер решает, парсер передумывает — вид узла перестаёт быть
  фактом, а становится черновиком, и каждый потребитель дерева обязан это учитывать.
- **Сузить лексическую догадку**: после `type` + идентификатор требовать `=` или `<`, пропуская
  комментарии. Отвергнуто: приближение, а не правило — совпадает на известных формах и
  расходится на следующей; Оригинал здесь отвечает разбором, и повторить это лукахедом нельзя.
