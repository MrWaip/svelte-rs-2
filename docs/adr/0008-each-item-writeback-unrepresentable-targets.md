# 8. Writeback-места each-item, которые Оригинал печатает невалидным JS

Статус: принято (2026-07-26)

## Контекст

В legacy-mode запись в переменную, объявленную деструктурирующим контекстом `{#each}`
(`{#each rows as [first, ...rest]}`), идёт через **writeback-место** — выражение-цель
присваивания, собираемое из пути переменной в паттерне. Оригинал строит его в
`extract_paths` (`update_expression`) и подставляет в `assign`/`mutate` без проверки, что
получившееся выражение вообще является легальной целью присваивания в JS.

Для части форм эта цель — вызов, и Оригинал печатает синтаксически невалидный JavaScript:

- array-rest: `$$array.slice(1) = $$value`
- object-rest: `$.exclude_from_object($.get($$item), ['name']) = $$value`
- update-выражение над любой деструктурированной переменной: `count()++`

Такой вывод не парсится: он падает при загрузке модуля. Для rest-переменных Оригинал вдобавок
сам предупреждает `bind_invalid_each_rest` — «биндинг с оригинальным объектом работать не
будет», то есть код заведомо мёртвый.

Наш backend строит выходной JS как OXC AST. `AssignmentTarget` / `SimpleAssignmentTarget` в
OXC не имеют варианта для вызова — эти формы в нашем представлении **непредставимы** в
принципе, а не «не реализованы». Харнес их тоже не удержит: `just generate` прогоняет
референсный вывод через OXC-парсер, и невалидный JS даёт пустой ожидаемый снапшот.

## Решение

Парити по этим формам не держим и кейсов на них не заводим.

1. **Writeback-место заводится только для представимых целей.** Переменная получает место,
   если её путь не заканчивается срезом (array-rest) и она не object-rest; всё остальное
   (ключ, индекс, вложенные комбинации, значение по умолчанию) место получает.
2. **Отсутствие места не меняет getter.** `bind:` на rest-переменной эмитит обычный
   each-item accessor на чтение, а на запись — ту же invalidation-последовательность без
   присваивания. Чтение работает, запись — no-op, ровно то поведение, о котором Оригинал и
   предупреждает.
3. **Update-выражения** (`count++`) над деструктурированными each-item переменными
   оставлены как есть.

## Альтернативы

- **Вердикт «место представимо» в анализе** (`BindingSemantics` / `HtmlBindKind`), чтобы
  кодген не решал этого сам. Отвергнуто: непредставимость — свойство OXC-представления
  выходного JS, то есть emit-форма; нести её в семантике запрещает
  `context.md` § «Codegen-агностичность анализа». Плюс `destructuring.md` § инвариант 4
  прямо отдаёт структуру паттерна (rest, путь, срез) потребителю через `walk_bindings`.
- **Представить вызов как цель присваивания** — обёрткой поверх OXC-типов или печатью в
  обход AST. Отвергнуто: ломает единственный путь печати и тиражирует невалидный JS.
- **Заводить кейсы с пустым ожидаемым снапшотом.** Отвергнуто: пустой `case-svelte.js`
  ничего не проверяет и читается как «должны совпасть», хотя совпасть нельзя.

## Последствия

- Панику `bind without getter/setter must be bind:this` на `bind:` к rest-переменной
  заменяет валидный вывод; он отличается от Оригинала, но Оригинал здесь печатает то, что
  не запускается.
- Формы с представимой целью (индекс массива, вложенность, значение по умолчанию, ключ
  внутри rest) закрыты кейсами кластера `each_item_writeback`. Правило самого места —
  `destructuring.md`.
- Осознанное отступление от «100% парити»: см. `CLAUDE.md` § «Porting from Svelte compiler» —
  это второе такое исключение после инъектнутого CSS (ADR 3).
