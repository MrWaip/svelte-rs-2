# 3. Инъектнутый CSS сверяется семантически, не побайтово

Статус: принято (2026-07-18)

## Контекст

Инъектнутый CSS (`$$css.code`, режимы `css: injected` и custom element) встраивается
строковым литералом в выходной JS обоих target'ов. Побайтовая сверка JS ловит его как
mismatch, хотя семантически CSS идентичен эталону:

- Оригинал печатает injected CSS через MagicString поверх исходника: в dev сохраняет
  авторское форматирование (табы, пустые строки, комменты) и лишь вплетает scope-хеш,
  неиспользуемые правила оборачивает в `/* (unused) */` вместо удаления, минифицирует только
  при `!dev`; в prod срезает точечный whitespace, но каркас исходника оставляет (`--custom: val`
  не схлопывает, `\n` между comma-селекторами и в `@media`-прелюдии сохраняет).
- Наш backend печатает CSS из AST и минифицирует `$$css.code` в обоих режимах, unused удаляет.
  Байтовое парити в dev недостижимо без source-preserving печати (авторские табы/пустые строки
  из AST не реконструировать), а prod-«минификация» Оригинала — это «исходник минус точечный
  whitespace», которую глобальный минификатор не воспроизводит.

## Решение

Injected CSS сверяется **семантически**. Наш вывод остаётся минифицированным (чище), а точки
сверки перед сравнением JS переминифицируют `$$css.code` обеих сторон через lightningcss.

1. **Единый нормализатор** `test_support::canonicalize_injected_css_in_js`: находит `$$css.code`,
   срезает `/*# sourceMappingURL … */`, минифицирует через lightningcss (`minify: true`), вклеивает
   обратно; при неудачном парсе — fallback на нормализацию пробелов + `strip_reference_only_css_markers`.
   JS вне `$$css` не трогается.
2. **Во всех точках сверки с Оригиналом**: харнес (`test_v3.rs`, `test_clusters.rs`), quick-check,
   sweep — все переиспользуют один нормализатор из `test_support`.
3. **Ловит реальные css-баги** (другой хеш/селектор, потерянная/лишняя декларация, другое значение);
   игнорирует только форматирование, комменты и sourcemap.

## Последствия

- Injected-CSS-расхождение перестаёт шуметь в харнесе / quick-check / sweep; инъектные кейсы
  переведены в активные (`[prod, dev, ssr, ssr_dev]`).
- Компилятор не менялся — правится только сравнение; наш минифицированный вывод сохраняется.
- Sourcemap injected CSS в dev парити не держит (разный текст → разные mappings по построению);
  наш map корректен для нашего вывода, просто не сверяется.
- `lightningcss` — dev-зависимость `test_support`, в компилятор не попадает.
- Единственное место, где выходной JS намеренно не байт-парити с Оригиналом.

## Альтернативы

- **Переписать печать CSS на source-preserving (MagicString-порт).** Достигает байт-парити, но
  тащит чужой механизм (сохранение авторского форматирования, коммент-обёртки unused) в наш вывод
  ради «грязного» вывода Оригинала. Отвергнуто: наш минифицированный вывод чище, парити держится
  семантически.
- **Свой `svelte_css`-парсер для нормализации вместо lightningcss.** Отвергнуто: lightningcss —
  battle-tested семантика, уже лежит в основе нормализатора `test_support`; свой канон рисковее по покрытию.
- **Сверять только структуру JS, `$$css.code` бланчить.** Отвергнуто: перестаёт ловить реальные
  css-баги внутри инъекта.
