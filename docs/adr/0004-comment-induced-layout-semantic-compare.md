# 4. Комментарии и вызванная ими вёрстка сверяются семантически

Статус: принято (2026-07-19)

## Контекст

Наш компилятор бережно проносит авторские комментарии из исходника в выходной JS
(`/* @vite-ignore */`, `// eslint-disable-…`, JSDoc `/** @type … */`) — они несут смысл для
сборщика и тулинга. Оригинал их отбрасывает.

Печать через `oxc_codegen` при наличии комментария рядом с узлом переключает вёрстку на
многострочную — заметнее всего в динамическом `import(...)`: аргумент с комментарием
печатается «столбиком» (`import(\n\t/* … */\n\turl\n)`), тогда как Оригинал печатает
`import(url)` в строку. Прежний нормализатор `strip_js_comments` срезал только текст
комментария, но не схлопывал вызванную им многострочность, из-за чего кластер модулей
(`chunk-*.svelte.js`, dynamic-import) шумел как расхождение при семантически идентичном коде.

## Решение

Комментарии и их влияние на вёрстку сверяются **семантически**. Наш вывод остаётся
комментированным (богаче), а точки сверки перед сравнением переразбирают и печатают JS без
комментариев.

1. **Единый нормализатор** `test_support::canonicalize_js`: парсит JS как модуль и печатает его
   заново через `oxc_codegen` с `CommentOptions::disabled()`. Это разом убирает и текст
   комментариев, и вызванную ими многострочную вёрстку. При ошибке парса — fallback на прежний
   текстовый `strip_js_comments`.
2. **Во всех точках сверки с Оригиналом**: харнес (`harness.rs`), quick-check, sweep — все
   переиспользуют один нормализатор из `test_support` (совмещён с
   `canonicalize_injected_css_in_js` из ADR 0003).
3. **Ловит реальные js-баги** (иная структура AST → иная печать); игнорирует только
   комментарии и продиктованное ими форматирование.

## Последствия

- Коммент-расхождение перестаёт шуметь в харнесе / quick-check / sweep.
- Компилятор не менялся — правится только сравнение; наш комментированный вывод сохраняется.
- Сверка JS теперь идёт через переразбор+печать oxc (сравнение на уровне AST, а не побайтово):
  чисто-форматные различия между esrap и oxc также нивелируются. Зелёные кейсы остаются
  зелёными (одинаковый после нормализации текст → одинаковый AST → одинаковая печать).
- Второе (после injected CSS, ADR 0003) намеренное отступление от побайтового JS-парити.

## Альтернативы

- **Деградировать наш codegen под отбрасывание комментариев Оригиналом.** Отвергнуто: наш
  вывод бережнее, комментарии семантически значимы (`@vite-ignore`).
- **Схлопывать многострочность текстово в `strip_js_comments`.** Отвергнуто: воспроизвести
  правила вёрстки oxc текстом хрупко; переразбор+печать — надёжный канон.
