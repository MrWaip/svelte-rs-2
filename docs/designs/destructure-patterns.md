# PRD: destructure patterns — обход и разворот

Дочерний PRD кластера `reactivity-semantics`. Охватывает обе оси работы с деструктурирующими паттернами:
объявление (`BindingPattern`, ось `binding_semantics` / `declarator_semantics`) и присваивание/мутация
(`AssignmentTarget`, ось `reference_semantics`). Закрывает развилку парности: в runes-режиме
деструктур-присваивание рунам не разворачивается (кластер `destructure_assignment_runes` — запись идёт мимо
сигнала, UI не обновляется), и канонизирует обход паттерна, убирая ручные `match`-обходы из разворотов.

Оригинал для «что»: `original/compiler/` — `build_assignment` + `extract_paths` (общий разбор путей паттерна для
объявлений и присваиваний). Архитектура — наша.

## Назначение

Единый ответ компилятора на вопрос «как добраться до значения каждого target-а/биндинга деструктурирующего
паттерна и что с ним сделать», валидный для всех форм паттерна на обеих осях. Сегодня обход паттерна в разворотах
катается руками (`match BindingPattern` в разворотах объявлений, `match AssignmentTarget` в legacy-присваивании),
а runes-присваивание через паттерн не разворачивается вовсе.

## Карта форм (что закрываем) — fork-set из Оригинала

Ось присваивания (`destructure_assignment_runes`):

- array-паттерн / object-паттерн как target присваивания;
- RHS-литерал против RHS-идентификатора (форма обёртки);
- дефолт на листе и на промежуточном узле (`[a = 5]`, `[{ a } = {}]`) — оборачивается в `$.fallback`;
- array-rest (`[a, ...b]`) — `$.to_array` без счётчика + `.slice(n)`;
- object-rest (`{ a, ...rest }`) — `$.exclude_from_object`;
- вложенность (`[[a]]`, `[{ a }]`), array-дырки;
- computed-ключ (`{ [k]: a }`);
- смешанные target-ы (`[obj.x, a]`) — member-target рядом с сигнальным;
- позиция-значение (`let x = ([a] = arr)`) — `return` RHS из обёртки;
- async (`[a, b] = [1, await …]`, `[a = await …]`) — `async`-обёртка + `await`, ленивый `$.fallback`;
- guard: ни один target не реактивен (`[x, y] = [1, 2]` из локалей) — паттерн остаётся нетронут;
- guard: одиночный идентификатор (`a = 5`) — обслуживается обычным дисптчером записи, вне разворота.

Ось объявления (канонизация обхода, без изменения поведения): `$state` / `$derived`-destructure, `{@const}`,
`let:`-директива, `$props()`, legacy `export let` — каждый разворот переходит на канонический обходчик.

Применимо и к standalone-модулям `.svelte.js` / `.svelte.ts` (`compile_module`): разворот write-оси тот же;
шаблонных форм там нет.

## Public API

`ComponentSemantics` (раздел обхода паттернов):

- `walk_bindings` — существующий канонический обходчик `BindingPattern` (binding-ось). Остаётся единственным
  санкционированным способом обойти `BindingPattern`.
- `walk_assignment_targets` — новый канонический обходчик `AssignmentTarget` (write-ось), сестринский к
  `walk_bindings` по схеме. На каждый target отдаёт: сам target (`WriteTarget` — identifier-ссылка либо
  member-target), путь от корня (`WriteStep` с `WriteAccess::Index { index, len, has_rest }` / `Key` / `Computed`),
  дефолт на шаге, признак rest, исключённые ключи для object-rest. Identity target-а — `ReferenceId` (для
  identifier) либо корневая ссылка member-а; символов-биндингов write-ось не несёт.
- `walk_assignment_target_idents` — становится тонким фильтром поверх `walk_assignment_targets` (нужен потребителям,
  которым достаточно простых identifier-target-ов, например legacy `$:`-трекинг зависимостей).

Анализ новых точек расширения не получает. Смысловой источник по target-у/биндингу — три существующие точки
(`binding_semantics`, `declarator_semantics`, `reference_semantics`); запись через паттерн уже классифицирована в
`reference_semantics` (листы паттерн-присваивания помечаются write на generic-слое).

## Архитектурные инварианты

1. **Один обходчик на ось.** `walk_bindings` для `BindingPattern`, `walk_assignment_targets` для
   `AssignmentTarget`. Ручной `match` по дереву паттерна ради обхода запрещён на обеих осях (дисциплина
   `bindings-and-references` §5). Ручной `match` допустим только для распознавания конкретной формы, не для обхода.
2. **Граница шеринга — только обходчик.** Общего рантайм-билдера сборки доступа нет. Сборку `$.to_array` /
   `$.fallback` / `$.exclude_from_object` / `.slice` каждый разворот собирает у себя из пути, отдаваемого
   обходчиком. Это сознательный выбор: меньше связанности, нет кросс-осевой доработки формы пути.
3. **Анализ не меняется.** Write-листы уже помечены write → `reference_semantics`; binding-ось — `binding_semantics`
   / `declarator_semantics`. Никаких новых side-таблиц и вариантов под эту фичу.
4. **Тупой трансформ / кодген.** Смысл target-а/биндинга — один запрос (`reference_semantics` через пять
   диспетчеров записи / `binding_semantics`). Структура (путь, темпы, дефолты, rest) — обход + сборка доступа, без
   реклассификации реактивности и без пересбора наличия `await`.
5. **Без эмит-формы в анализе.** `$.to_array` / `$.fallback` / `$.exclude_from_object` строятся трансформом /
   кодгеном, в семантику не утекают. Выбор обёртки (последовательность / обёртка-функция / async-обёртка) —
   локальное структурное решение по форме AST, аналог классификации содержимого фрагмента в кодгене, а не смысл.

## Разворот (client emit)

Диспетч по виду — исчерпывающий: для объявления — по `declarator_semantics`, для записи — категория
деструктур-присваивания, далее каждый target через пять диспетчеров записи (`reference_semantics`).

Присваивание (write-ось):

- guard: разворот включается только если хотя бы один target реактивен по `reference_semantics`
  (сигнальная запись / store / derived / legacy-state); иначе паттерн остаётся нетронут.
- обход через `walk_assignment_targets`; на каждый target из пути собирается выражение доступа: `$.to_array` со
  счётчиком элементов (без счётчика при наличии rest) с переиспользованием темпа-массива по префиксу пути,
  индексный доступ, `.slice` для array-rest, member / computed для объекта, `$.exclude_from_object` для object-rest,
  `$.fallback` для дефолтов (ленивая форма и `await` в async-ветке).
- обёртка результата: последовательность (только object-паттерн при простом идентификаторе-RHS), иначе
  обёртка-функция (имя параметра — имя идентификатора-RHS либо служебное), async-обёртка с `await` при наличии
  `await` в RHS или дефолтах; `return` RHS из обёртки в позиции-значении.
- сеттер на target: identifier — через дисптчер записи идентификатора (сигнал на выходе даёт `$.set(.., needs_proxy)`
  по обычному правилу `should_proxy`; plain-локаль — обычное присваивание; store / derived / legacy-state — там же);
  member-target — через дисптчер member-записи (обычное присваивание члена).
- точка входа — на выходе обхода выражения, на месте существующего legacy-хука разворота деструктур-присваивания;
  legacy-режим обслуживается тем же разворотом (его поведение задаётся семантикой target-а, не отдельной веткой).

Объявление (binding-ось): каждый разворот (`$state` / `$derived`, `{@const}`, `let:`-директива, `$props()`,
legacy `export let`) обходит `BindingPattern` через `walk_bindings`; ручной `match BindingPattern` уходит. Сборка
доступа (включая обёртку темпа-массива в `$.derived` для реактивных объявлений) — частная для каждого вида.
