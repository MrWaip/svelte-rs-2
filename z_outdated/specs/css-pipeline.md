- [x] Sibling-combinator selector matching across mutually recursive snippet bodies terminates instead of stack-overflowing. Two snippets `a`/`b` whose bodies render each other through `{@render b()}` / `{@render a()}` form a cycle in the render-tag → snippet edge graph that `css_prune` follows when expanding the possible-siblings set for a `div + div` rule. `svelte_analyze::passes::css_prune::get_possible_element_siblings` now takes `seen_snippets: &mut FxHashSet<NodeId>` and the recursive call in `collect_possible_siblings`' `Node::SnippetBlock` arm threads it through, matching reference's `seen` parameter at `css-prune.js:1070`. The `pruner.index.cached_siblings` lookup/store is gated on `seen_snippets.is_empty()` so mid-cycle (cycle-truncated) results do not poison the cache (test: `diagnose_css_recursive_snippet_sibling_overflow`).
- [x] `{@render <name>()}` to a `SnippetBlock` declared textually after the current snippet emits a direct call (`b(node)`) instead of the `$.snippet(node, () => b)` indirection. Root cause was that `ComponentSemanticsBuilder` accumulates `root_unresolved_references` through every mini-program's `JsSemanticVisitor::flush_unresolved` (each template expression / snippet decl is parsed as its own oxc sub-program) but never performed a component-level closing pass after all `add_*_program` / `add_template` calls finished. OXC's own `resolve_references_for_current_scope` (oxc_semantic builder.rs:520) closes the loop on every scope-exit, but our mini-program flow has no component-root scope-exit hook — forward sibling refs (e.g. `b` inside snippet `a` when `b` is declared later) stayed parked in `root_unresolved_references` forever. Fix: `ComponentSemantics::finalize_unresolved_references` runs one final sweep mirroring OXC's resolution algorithm — for each parked `(name, ref_ids)`, walk the scope chain from `Reference.scope_id()` via `find_binding(scope, name)`; on a match set the reference's `symbol_id` and call `add_resolved_reference`. Called from `crates/svelte_analyze/src/passes/build_component_semantics.rs` right after `builder.add_template(...)`. All downstream consumers (`RenderTagBlockSemantics.callee_sym` via `callee_symbol`, `finalize_hoistable` snippet-name taint check, `ReactivitySemantics` reference classification) now see resolved `symbol_id()` for forward sibling refs through the existing id-graph — no name-based shortcuts in consumers, §3.A.1 «Identity by id» preserved (test: `diagnose_css_recursive_snippet_sibling_overflow`).

## Out of scope

- CSS source maps; tracked in `specs/source-maps.md`
- Custom-element default CSS injection behavior outside the main component CSS pipeline
- SSR-specific CSS behavior
- Emitting `/* (unused) <source> */` comments for pruned style rules and `/* :global {*/ … /*}*/` wrappers around lone `:global { … }` blocks — reference does this because its CSS transform is MagicString-based text replacement that cannot delete nodes without leaving a marker. Our pipeline is AST-based: `svelte_transform_css::ScopeSelectors` hoists `is_lone_global_block()` children up and `svelte_css::Printer` drops unused rules entirely (gated by `remove_unused`). The textual divergence vs reference is intentional; the snapshot harness absorbs it via `tasks/generate_test_cases/src/main.rs::strip_unused_css_comments` (strips `/* (unused) … */` from `case-svelte.css`) and `tasks/compiler_tests/test_v3.rs::normalize_css` (filters comment-only lines). Do not re-open this as a parity gap — see `specs/unknown.md` history for the rejected closure attempt.
