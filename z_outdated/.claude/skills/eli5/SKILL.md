# eli5

Пользователь — верхнеуровневый владелец кодовой базы, написанной ИИ. Не сыпать деталями, путями, идентификаторами. Цель: чтобы он понял суть за 10 секунд.

## Формат ответа (строгий)

1. **Один абзац ≤5 строк** — суть простыми словами. Без списков, без подзаголовков, без имён файлов и функций.
2. **Блок Svelte input** — минимальный пример (3–8 строк), который иллюстрирует разговор.
3. **Блок «наш выход»** — что выдаёт наш компилятор (JS, ≤15 строк, обрезать неважное `// ...`).
4. **Блок «reference выход»** — что выдаёт `svelte/compiler` для того же ввода (≤15 строк, обрезать так же).
5. **2–3 предложения пояснения** — в чём ключевая разница/смысл. Не больше.

## Правила

- Всегда упрощать, даже если вопрос сложный. Жертвовать точностью ради понятности.
- Никаких "однако", "стоит отметить", "важно понимать". Прямой текст.
- Никаких путей `crates/...`, имён функций, NodeId/SymbolId — это шум.
- Если для вопроса код Svelte не нужен (вопрос про процесс/архитектуру) — давать только пункт 1 и пункт 5, без блоков кода.
- Если не знаешь точный выход компиляторов — запустить `quick-check` skill или прочитать соответствующий case в `tasks/compiler_tests/cases2/`. Не выдумывать.
- Аналогии из жизни приветствуются, если помогают.

## Пример (так надо)

> Реактивные переменные превращаются в геттер/сеттер. Когда ты пишешь `count = 1`, компилятор подменяет это на вызов функции, которая дёргает все зависящие куски DOM.
>
> Svelte:
> ```svelte
> <script>let count = 0;</script>
> <button on:click={() => count++}>{count}</button>
> ```
>
> Наш и reference дают одинаковый JS с `$.state(0)` и `$.set(count, ...)`.
>
> Разница: мы пока не инлайним `$.get` для одиночных чтений, reference — инлайнит. На поведение не влияет, только размер бандла.
