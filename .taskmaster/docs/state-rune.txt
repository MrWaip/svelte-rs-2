# PRD: $state rune

Дочерний PRD кластера `reactivity-semantics`, ось — runes.

## Назначение

Декларация реактивного состояния компонента/класса/модуля через руну `$state`.

## Формы

- `$state(value)` / `$state()` — глубоко-реактивное. Аргумент-объект/массив рекурсивно оборачивается в `$.proxy`; примитивы, class-instance и объекты, созданные `Object.create`, **не оборачиваются** в `$.proxy`.
- `$state.raw(value)` — поверхностно-реактивное, **никогда не оборачивается** в `$.proxy` (включая class-field и `this.x = $state.raw(obj)` в конструкторе). Допускает только переприсваивание, не мутации полей.
- `$state.snapshot(value)` — снапшот в plain JS через `$.snapshot`; принимает `is_ignored`-флаг для подавления предупреждения.
- `$state.eager(expr)` — eager-derived для немедленного UI-фидбэка без ожидания async-синхронизации; декларация дропается, чтения/записи трактуются как plain JS.

## Места использования

- `VariableDeclarator` (top-level и внутри функций),
- public/private class field,
- assignment в конструкторе на `this.field` / `this.#field` (только первое присваивание),
- destructuring (object + array) — для обеих форм.

Допустим как в `.svelte`-компоненте, так и в standalone-модулях `.svelte.js` / `.svelte.ts` (pipeline `compile_module`).

Любая другая позиция — error `state_invalid_placement`. Destructure теряет реактивность — стандартная JS-семантика, не наша проблема.

## Client emit

- **Wrapping.** Кодген оборачивает биндинг в `$.state` на выходе, если он мутируется или участвует в destructure. Иначе мутируемый примитив остаётся голым значением (оптимизация — отдельный вариант `BindingSemantics`).
- **`$.proxy`.** Применяется только к `$state` и только для plain-object/array. Class-field с не-литералом (`current = $state(DEFAULTS)`) явно оборачивается в `$.proxy`. `$state.raw` — никогда.
- **Reads.** `$.get` в общем случае; `$.safe_get` для `var`-декларированных (hoisting); прямое чтение внутри тела конструктора в фазе инициализации поля.
- **Writes / updates.** `$.set` / `$.update` / `$.update_pre` под `=` / `+=` / `++` / `--` и compound-assign (`&&=`, `||=`, `??=`).
- **Class fields.** Private backing-поле + публичные `get`/`set` на прототипе, вызывающие `$.get` / `$.set` по этому полю. Эти свойства не enumerable.
- **Member assignment dev.** Compound-assign по member-LHS заменяется парными хелперами `$.assign_nullish` / `$.assign_and` / `$.assign_or`.
- **Cross-module export.** Прямой `export let count = $state(0)` запрещён при последующем переприсваивании (см. валидацию). Разрешённые формы: `export const counter = $state({...})` (мутируется поле, не биндинг) или `let count = $state(0); export function getCount(){…}`.

## Server emit

Заглушка — ожидает `/audit`. Общие правила SSR для рун — в `ssr-pipeline`.

## Dev-инструментирование

- `$.tag` для каждого `$.state` — включая `.svelte.js`/`.svelte.ts` standalone.
- `$.tag_proxy` для оборачиваемых в `$.proxy` props/state.
- Лейблы destructure: `ArrayPattern` → `[$state iterable]`; nested array carrier под `ObjectPattern` → `[$state object]`.

## Валидация (3.C)

Errors: `state_invalid_placement`, `state_too_many_args`, `state_frozen_renamed`, `state_is_removed`, `state_invalid_export`.
Warning: `state_referenced_locally` (чтение state/derived на той же глубине функции — захват исходного значения).

## Контракт с `ReactivitySemantics`

Использует варианты:

- `BindingSemantics::State`, `BindingSemantics::OptimizedRune`.
- `DeclaratorSemantics::ClassFieldState`.
- `ReferenceSemantics::SignalRead`, `SignalWrite`, `SignalUpdate`, `Proxy`.

`$state.snapshot` / `$state.eager` биндингов не создают (callee-формы).
